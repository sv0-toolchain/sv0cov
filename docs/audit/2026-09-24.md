## SPEC §3.3 observed facts

Paths are relative to the `sv0-toolchain` checkout at `ff10e18`.

| # | SPEC §3.3 fact | Status | Evidence |
|---|---|---|---|
| 1 | sv0c pipeline: tokenize → parse → resolve → check → analyze/strip → lower → emit C or VM. | **Held** | `sv0c/lib/megaTU-modules.list` orders `lexer`, `parser`, `resolver`, `checker`, `contract_analyzer`, `ir`, `lowering`, `codegen`, `bytecode`, `vm_codegen`, `link`. The native compiler is the assembled mega-TU. |
| 2 | `span.sv0` defines spans with file path, start/stop line/column, byte offsets. | **Held, with a qualification** | `sv0c/lib/span.sv0` `struct Span` (lines 16–24). All numeric fields are `i32`, and columns are byte-based rather than Unicode-scalar (SPEC §7 requires scalar display columns). |
| 3 | AST expressions and statements carry span handles. | **Held** | `sv0c/lib/ast.sv0` header ("Span is i32 handle throughout"), e.g. `ExprIf(…, i32, i32)` line 64, `StmtLet(…)` line 90. |
| 4 | Lowered IR carries no coverage-ready provenance. | **Held** | `sv0c/lib/ir.sv0` `enum Instr` (lines 27–45) has no span field. The header notes that 4 payloads is the per-variant maximum. |
| 5 | Generated-C backend emits structured control flow from lowered instructions. | **Held** | `sv0c/lib/codegen.sv0` `emitInstr` handles `IfElse` / `While` / `Block` (header lines 4–5, match at line 360). |
| 6 | `.sv0b` has strings, functions, and code, with no coverage or source-map section. | **Held** | `sv0vm/src/bytecode/bytecode.sml` `encodeFile` / `decodeFile` (lines ~495–550): header `SV0B` + `u16` version `1`, then string, function, and code sections. | 7 | sv0vm has a central dispatch loop and a builtin-call path. | **Held** | `sv0vm/src/interpreter/interpreter.sml` `step` (line 469), `CALL_BUILTIN` dispatch (line 720). |
| 8 | Project compilation discovers and sorts `.sv0` sources; link helpers compute concatenated offsets that are not a canonical coverage map. | **Held** | `sv0c/lib/link.sv0` `walk_sv0` (line 56; sorted lexicographically, comment line 51), `link_project_concat_sources_from_dir` (line 786), `link_second_file_byte_offset_after_concat` (line 1534). Project mode compiles one concatenated TU, so every span offset is concat-relative. |
| 9 | Grammar permits item attributes; the parser skips them. | **Changed** | Still skipped generically by `ps_skip_attributes` (`sv0c/lib/parser.sv0` line 325), but `#[extern_c]` is now recognized specially by `ps_peek_extern_c_attribute` (line 311, FFI-008). `sv0doc/grammar/sv0.ebnf` has `attributed_item` (line 684) and no statement-attribute production. |
| 10 | The lexer discards line comments. | **Held** | `sv0c/lib/lexer.sv0` `skip_ws` / `skip_line_comment` / `skip_block_comment` (lines 234–256). |
| 11 | No repository provides the coverage lifecycle. | **Held** | `COVER_HIT` and `sv0cov` do not appear in `sv0c/lib`, `sv0c/runtime`, `sv0vm/src`, or `sv0doc`. The only "coverage" matches are unrelated prose comments. |

## Additional findings

These are recorded as gaps `G-1`…`G-10` in the planning hub
(`sv0-toolchain/task/sv0cov-coverage.Rmd`).

| ID | Finding | Evidence | Disposition |
|---|---|---|---|
| G-1 | No typed v2 bytecode container exists. v2 is defined only by the draft `project-specs/sv0vm-implementation-expand/SPEC.md` (version 0.1.35), targeted at that program's R0.6. | `sv0vm/src/bytecode/bytecode.sml` (`formatVersion = 1` only) | Resolved by SPEC amendment `0.1.71-draft` (DEC-086, §15.6): v2 coverage evidence is staged to R1. |
| G-2 | No SHA-256 implementation exists in sv0c, the C runtime, or sv0vm. sv0c needs it for source digests, point IDs, fragment IDs, and `map_id`. | Repository search. `task/sv0-toolchain-milestone-5-checklist.Rmd` `M5-S-040a/b` are `todo`. | Open decision D-2. |
| G-5 | Project mode concatenates every source into one TU, so span offsets are concat-relative. | Fact 8 evidence | Planner needs a concat-offset → (logical path, file-relative byte) table (CV-105). |
| G-7 | Opcode 119 is free. | `bytecode.sml`: 118 = `RETURN_SLOTS`, next assigned is 128. The expansion spec's opcode table also leaves 119 unassigned but rejects every unlisted opcode. | Reserve in sv0doc (CV-101) and register in the expansion spec. |
| G-8 | sv0 has no process API (spawn/fork/exec) in the language, C runtime, or VM. Native entry is `sv0_runtime_init(argc, argv)`; contract failure exits through `exit(1)` in runtime header helpers. | `sv0c/runtime/sv0_runtime.h`, `sv0c/lib/megaTU-main.sv0` hosted `main` emission | Open decision D-4. |
| G-9 | On the audit host, `python3.13` / `python3.14` resolve to pyenv shims, which the SPEC §20.6.4 launcher rejects by design. | `which python3.13 python3.14` → `~/.pyenv/shims/` | Local development needs a real CPython earlier on `PATH`. |
| G-10 | Contract modes map onto SPEC enforcement dispositions: model-only clauses (`old`/`forall`/`exists`) → `unsupported`, contracts off → `disabled`, `sv0 verify` discharged → `statically_verified`. | `sv0doc/contracts/semantics.md` §3.1–§3.2 | Used by the contract planner (CV-306). |
